Dash is one network with two layers that do different jobs. **Dash Core** is the layer 1 blockchain for digital money. **Dash Platform** is the layer 2 application and data layer built on top of it.

That distinction matters when you build an app. Core moves and secures Dash payments. Platform gives your app decentralized identities, structured data storage, queries, and verifiable access to data.

## The two layers

| | Dash Core (layer 1) | Dash Platform (layer 2) |
| --- | --- | --- |
| Primary job | Payments and the Dash asset | Application identities and data |
| Typical activity | Send or receive Dash | Create identities, register data contracts, and submit or query documents |
| Developer access | Core RPCs or DAPI | DAPI and Platform SDKs |

Platform can read information from Core, but Core does not depend on Platform. This keeps application activity from changing the payment layer's job.

<Callout type="info" title="One network, not two unrelated products">
Core and Platform share Dash's masternode infrastructure. DAPI exposes both layers through one decentralized API, and Dash locked on Core can fund Platform credits used to pay Platform fees.
</Callout>

## What developers build with

Platform replaces the usual combination of a hosted application database, a single API provider, and application-specific account identifiers with network primitives.

- **Identities** are public, cryptographic actors. They sign changes and own Platform data.
- **Data contracts** are JSON Schema-based definitions that describe the structure and rules for an application's data.
- **Documents** are the individual records stored under a data contract, similar to records in a document database.
- **Drive** stores and indexes Platform state across the masternode network.
- **DAPI** lets clients submit state changes and query both Platform and Core without running their own node.

When a user changes application data, a client creates a signed **state transition**. Platform validates it against the protocol and the app's data contract, orders it on the Platform chain, and applies the resulting state to Drive. A later query can include a cryptographic proof, allowing the client to verify the response instead of simply trusting the server that returned it.

## What Platform is—and is not

Dash Platform is a decentralized application stack, but it is not an environment for deploying arbitrary user-written smart contract code. Developers define schemas and submit structured state transitions. The network handles validation, storage, indexing, consensus, and proofs around those shared rules.

This approach is useful when an application needs structured public data with shared integrity: profiles, social relationships, names, marketplace records, tokens, or other records that multiple clients should be able to read and verify.

The shortest useful mental model is:

> **Core moves value. Platform gives applications identity and verifiable data. DAPI is the way clients reach both.**
