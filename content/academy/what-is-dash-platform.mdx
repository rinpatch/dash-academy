## Learning objectives

By the end of this lesson, you will be able to:

- explain what a blockchain network offers an application developer;
- separate Dash Core's job—moving money—from Dash Platform's job—storing app data;
- name concrete kinds of applications you can build on Dash; and
- outline the application you will build, end to end, later in this course.

Dash splits one network into two connected layers with different jobs. In this lesson you will meet both halves, see what a developer can build with them, and preview the app you will build yourself over the rest of this course.

## What a blockchain network gives you

A blockchain is a network of computers that independently agree on one shared, append-only record. The record is not kept in a single company's database; copies are spread across the network and reconciled through a consensus the network enforces rather than one operator deciding.

From an app developer's point of view, that shared record changes the deal:

- **Decentralized storage.** An application's data lives on many independent computers, so it does not depend on one company's server staying up or staying honest.
- **Shared state.** Any client that connects sees the same data and can cryptographically check that data is what the network agreed to.
- **Client libraries.** A software development kit (SDK) hides the low-level networking and cryptography, so you write ordinary application code instead of protocol code.

You do not have to run your own network node or build the cryptography yourself. You use the network the way you would use a backend service—except the backend belongs to no single company.

## One network, two jobs

Dash organizes that shared record into two layers so that one layer can stay focused on money while the other carries application data.

| | Dash Core | Dash Platform |
| --- | --- | --- |
| Layer | Layer 1 | Layer 2 |
| Job | Move value | Store and verify app data |
| What you submit | A payment transaction | A signed <Term id="state-transition">state transition</Term> |

**Dash Core** is the layer-1 blockchain. It is the money layer: it settles Dash payments and carries the Dash currency itself.

**Dash Platform** is the layer-2 application-data layer. It stores structured application data—the records behind usernames, profiles, listings, and other app state—and verifies that only authorized write operations change it.

The relationship runs one way: Platform can read what is on Core, but Core does not depend on Platform. That lets Dash add application capabilities without making the money layer responsible for application data.

<Callout type="info" title="A useful mental model">
Core is the payment rail. Platform is the database. They share one network, but each stays focused on its own job.
</Callout>

### How Platform stores data

On most blockchains, adding application logic means deploying a <Term id="smart-contract">smart contract</Term>—code the network runs for you. Dash Platform takes a different path: instead of uploading custom code, you **describe** your data.

- A **data contract** is a schema that declares the records your app may store—their fields, types, and indexes.
- A **state transition** is a signed operation that changes data, such as creating an identity, registering a name, or writing a record.
- The network validates every change against the contract and stores the result; there is no contract code of your own for it to execute.

Two components do the work behind the scenes:

- **Drive** is Platform's decentralized storage. It validates and keeps the network's application state.
- **DAPI** is the decentralized API. It exposes <Term id="json-rpc">JSON-RPC</Term> and <Term id="grpc">gRPC</Term> endpoints through a network of <Term id="masternode">masternodes</Term>, so your app can read and write Platform data and query the Core chain without running its own node.

## Payments confirm in about a second

Dash is built for payments, and speed is the point. A Dash payment reaches confirmation in **about a second**—the Dash documentation describes a transaction reaching confirmation in "little more than a second."

What does that buy a developer? For a seller, it means you can accept a Dash payment and treat it as done almost immediately, the way a card or cash payment feels, instead of waiting through several mined blocks before trusting that the money arrived. That gives a checkout or peer-to-peer payment flow <Term id="fiat">fiat</Term>-like speed at low cost—without a middleman holding the funds.

This speed comes from how the Dash network reaches agreement. The mechanics live in later lessons; for now, the effect is what matters: **fast, cheap confirmation you can build a payment experience around.**

## What you can build

The two layers combine into a toolkit. Here are concrete things developers build on Dash:

- **Usernames and identities.** The Dash Platform Name Service (DPNS) ties a human-readable `.dash` name like `alice.dash` to a Platform <Term id="identity">identity</Term>, a persistent account that owns data and signs the actions that change it.
- **Application data.** Publish a data contract and submit documents — individual data records stored on Platform — so users share verifiable records instead of trusting one app's database.
- **Fungible tokens** (interchangeable, one-like-another units). Create a configurable token for rewards, memberships, or loyalty points.
- **Non-fungible tokens.** Build unique, document-based NFTs for collectibles and digital goods.
- **Payments.** Accept Dash with about-a-second confirmation.

The Dash documentation's own tutorials walk through working examples: **Dashnote** (a small notes app built from contracts and documents), **DashMint Lab** (an NFT marketplace), and **DashPay** (payments addressed by username).

Note what is missing from that list: a marketplace for arbitrary user-deployed code. Platform gives you storage, validation, and signed operations—it does not run unrestricted programs on every node. You design the data and the rules around it in your own application code.

## What you will build in this course

The rest of this course is hands-on. Working entirely on <Term id="testnet">testnet</Term>, you will assemble one small application from end to end:

1. Connect to DAPI and make a verified read.
2. Derive and fund a Platform address.
3. Create a Platform identity.
4. Register a DPNS username.
5. Publish a data contract for your app's records.
6. Submit and query documents.
7. Transfer a document and run a purchase flow.
8. Create a native token and charge tokens for document operations.

By the final module, you will have touched every layer introduced here: the Core payment rail, Platform identities, names, data contracts, documents, and tokens—all without running your own node.
